# Project inputs

Current course guidance and AI permission are confirmed in `COURSE_UPDATE_2026-11-09.md`. The full rubric has not been released; do not treat that as missing user action or a blocker. The development environment and footage are already present. The following is the original preparation checklist, retained for reference:

- The complete assignment, individual submission rubrics, due dates, and any course rules about AI assistance. The original excerpt alone does not define all four deliverables.
- Team size, each person's coding/design/analytics experience, available hours, and the target demonstration computer.
- A short environment note: operating system, CPU architecture, existing Python/Node tools, whether terminal installs are allowed, and whether a GPU is available. The baseline should work without assuming a GPU.
- 3–5 representative climbing clips for local feasibility runs. Include a clear clip and a hard clip. Add a manifest with clip IDs, intended climber, route, camera conditions, attempt bounds, and permitted development/demo use.
- Permission for whoever is developing the app to inspect representative frames when debugging. The local analysis runs on footage without uploading it anywhere.
- Any existing code, package locks, or required course hardware/software.
- Examples of desired feedback or interface sketches, if available.

During evaluation, add independent human labels, the fixed development/test split, and notes from real users. These are human contributions and must not be fabricated.

## Tool access

Provide project-folder read/write access; a terminal for local environments, installs, running Python/Node/FFmpeg and tests; network access to official documentation, package registries, and the official pose-model download; and a local browser or browser-testing tool for localhost.

A private Git repository is useful for version history and team collaboration. A GitHub connector is optional. No general access to email, Drive, school accounts, cloud infrastructure, or unrelated folders is needed. Application runtime API keys are unnecessary for the required MVP.
